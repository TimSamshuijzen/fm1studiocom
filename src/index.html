FM-1 STUDIO

      

        CODE WORKSTATION
        WebAssembly FM-1 simulator
      

      

      
    


    

      
FM-1 Studio is a code workstation for the M-VAVE FM-1 synthesizer that runs in the
        browser. Write a program in C, compile it, and play it on a simulated FM-1.

      
The compiler, the program and the simulator all run in this page. There is no server side: your
        code stays in your browser. The page simulates the API of the FM-1 (fm1.h). It does
        not emulate the processors of the FM-1, so a program that works here can fail on a real FM-1.

      
FM-1 Studio is an independent open-source project
        [1].
        It is not affiliated with M-VAVE or JieLi.

Write a program

      
A program is written against fm1.h. VIEW FM1.H shows it, with the full documentation.
        A program defines three functions:


#include "fm1.h"

void setup(void) { }                        /* one time, before the first audio block */
void audio(int32_t *out, int frames) { }    /* each block: 256 stereo frames, signed 24-bit */
void loop(void) { }                         /* again and again: controls and screen */

      

        
PartFunctions

        
Screen, 240 x 240, RGB565fm1_lcd_fill_rect, fm1_lcd_blit

        
Keys and buttonsfm1_in, fm1_input_edges, fm1_input_note_edges

        
LEDsfm1_led_key

        
Encodersfm1_enc_take

        
MASTER potfm1_master

        
MIDI inputfm1_midi_take

      

      
    
        
  • COMPILE, or Ctrl + Enter, compiles the project and runs the program.
    • 
        
  • The demo project main.c uses all of the API: a small FM synthesizer with an
          arpeggiator, an echo and its own screen.
    • 
        
  • A project can have more than one file. The optional file fm1project.json says how
          the project is built: sources, include, define and
          flags.
    • 
        
  • The page keeps nothing between visits. SAVE downloads the project as a zip file, and LOAD reads
          it back. You can also drop a project zip file on the page.
    • 
      

      
The screen and input functions have the names and signatures of felucca-bsp
        [4].


      
Firmware gallery

      
The cards in the PROJECT panel load the source code of open-source FM-1 firmware from GitHub, at a
        fixed version, and compile it in this page. Each firmware is the work of its authors and has its
        own licence.

      

        
FirmwareVersionWhatRepositoryLicence

        
      

      
These firmwares do not use fm1.h. Each one has its own FM-1 for the browser inside:
        the page gives it the keys, and takes the sound, the screen and the LEDs. To add a firmware, see
        "Add a firmware to the gallery" in the README
        [1].


      
Firmware for a real FM-1

      
The FIRMWARE button makes an installable .fwsc package of an fm1.h project
        and downloads it. The first time, it loads a second compiler (52 MB): clang for the processor of
        the FM-1, the JieLi pi32v2
        [5].
        An adapter gives the program the functions of fm1.h on fm1-base
        [3],
        the open platform for FM-1 firmware, and felucca-bsp
        [4].

      
No package was tried on a real FM-1 yet. Before you install one, read
        "On a real FM-1"
        in the README: how to install a package, which FM-1 units it is for, and what to do when an install
        goes wrong. Keep M-VAVE's FM-1.fwsc on your computer.

      
On the FM-1, a program must keep to more rules than in this page:

      
    
        
  • C only, no C++.
    • 
        
  • float only. A double stops the build: write 0.5f,
          sinf, powf.
    • 
        
  • No malloc and no printf. The float maths and the string
          functions are there.
    • 
        
  • 464 KB of memory for the program and the platform together.
    • 
        
  • audio() is an interrupt. Do not draw in it, and draw only what changed.
    • 
      

      
The full list is in
        firmware/README.md.
        The compiler panel tells when a program does not fit the FM-1.


      
How it works

      
    
        
  1. The compiler is clang 8 and wasm-ld as WebAssembly, in a Web Worker: wasm-clang
          [2].
          The page downloads it the first time (about 60 MB). The output is one WebAssembly module.
    2. 
        
  2. The simulator runs that module on the audio thread of the browser (an
          AudioWorklet). For each block of 256 frames it calls loop() and then
          audio(). The page shows the screen and the LEDs, and sends the keys, the encoders
          and the MIDI messages.
    3. 
        
  3. The firmware build is a second worker, with clang 23 and ld.lld for pi32v2
          [5],
          built with Emscripten
          [7].
          It does the steps of fm1-base's own build. For the projects that were compared, the package is
          the same bytes as the one from that build with the same compiler.
    4. 
      

      
The application is one HTML file, and the files of the second compiler. The README
        [1]
        tells more.


      
Limits

      
    
        
  • The simulator's compiler is clang 8. A program whose main loop does not return cannot run.
    • 
        
  • A project holds text files only: about 570 files and folders at most.
    • 
        
  • The LEDs are on or off: the dim levels of some firmware are not shown.
    • 
        
  • GitHub gives the list of files of a repository 60 times in an hour to one address. A firmware
          of the gallery uses one or more of these for its first load.
    • 
        
  • FIRMWARE is for fm1.h programs in C. A firmware of the gallery has its own build in
          its repository. A package has no USB audio and no Bluetooth; USB MIDI in works.
    •
