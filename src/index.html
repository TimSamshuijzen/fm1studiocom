FM-1 STUDIO

      

        CODE WORKSTATION
        code - simulate - install
      

      

      
    


    

      
FM-1 Studio is a code workstation for the M-VAVE FM-1 synthesizer that runs in the
        browser. Write a program in C, compile it, test it in the FM-1 simulator, and install it on your real FM-1.

      
The compiler, the program, the simulator, the installer all run in this page. There is no server side: your
        code stays in your browser. The page simulates the API of the FM-1 (fm1.h). It does
        not emulate the processors of the FM-1, so a program that works here can fail on a real FM-1.

      
FM-1 Studio is an independent open-source project
        [1].
        It is not affiliated with M-VAVE or JieLi.

Write a program

      
A program is written against fm1.h. VIEW FM1.H shows it, with the full documentation.
        A program defines three functions:


#include "fm1.h"

void setup(void) { }                        /* one time, before the first audio block */
void audio(int32_t *out, int frames) { }    /* each block: 256 stereo frames, signed 24-bit */
void loop(void) { }                         /* again and again: controls and screen */

      

        
PartFunctions

        
Screen, 240 x 240, RGB565fm1_lcd_fill_rect, fm1_lcd_blit

        
Keys and buttonsfm1_in, fm1_input_edges, fm1_input_note_edges

        
LEDsfm1_led_key

        
Encodersfm1_enc_take

        
MASTER potfm1_master

        
MIDI inputfm1_midi_take

      

      
    
        
  • COMPILE, or Ctrl + Enter, compiles the project and runs the program.
    • 
        
  • The demo project main.c uses all of the API: a small FM synthesizer with an
          arpeggiator, an echo and its own screen. PROG-1, the first card of the gallery, loads another
          demo: a progressive rock band in an FM-1, vibe-coded by Hans Dam. SPACE-1, the second card, loads space
          funk: a synth bass, a drum machine, and laser shots, a flying saucer and sonar pings on the
          buttons. GAME-1, the third card, loads a game: NEON REEF, a vertical shooter. Fly with
          A, W, S and D, and fire with J.
    • 
        
  • A project can have more than one file. The optional file fm1project.json says how
          the project is built: sources, include, define and
          flags.
    • 
        
  • The page keeps nothing between visits. SAVE downloads the project as a zip file, and LOAD reads
          it back. You can also drop a project zip file on the page. A file main.c that you
          drop on the page makes a new project with it, and so does C code that you paste on the page with
          Ctrl + V, outside the editor.
    • 
      

      
The screen and input functions have the names and signatures of felucca-bsp
        [4].


      
Firmware gallery

      
The first three cards in the PROJECT panel, PROG-1, SPACE-1 and GAME-1, load the demo projects
        above. The other cards load the source code of open-source FM-1 firmware from GitHub, at a fixed version, and
        compile it in this page. Each firmware is the work of its authors and has its own licence.

      

        
FirmwareVersionWhatRepositoryLicenceReal FM-1

        
      

      
These firmwares do not use fm1.h. Each one has its own FM-1 for the browser inside:
        the page gives it the keys, and takes the sound, the screen and the LEDs. To add a firmware, see
        "Add a firmware to the gallery" in the README
        [1].


      
Firmware for a real FM-1

      
The FIRMWARE button makes an installable .fwsc package of an fm1.h project
        and downloads it. The first time, it loads the firmware compiler (52 MB): clang for the processor
        of the FM-1, the JieLi pi32v2
        [5].
        An adapter gives the program the functions of fm1.h on fm1-base
        [3],
        the open platform for FM-1 firmware, and felucca-bsp
        [4].
        For a firmware of the gallery with "yes" under "Real FM-1" in the table above, FIRMWARE does the
        steps of the firmware's own build instead, with the changes that you made in its files.

      
The INSTALL button makes the same package and writes it to an FM-1 over USB. A dialog shows the
        steps: read, connect the FM-1, install. It uses Web MIDI, so it needs Chrome or Edge. The firmware
        on the FM-1 checks the package and starts the update loader of the package, and that loader writes
        the program. The code that talks to the FM-1 is the installer of fm1-base
        [3].
        For a firmware of the gallery, the dialog also asks you to agree to keep to the licence of that
        firmware.

      
FM-1 Studio was tested on a real FM-1, with the newer flash chip (B36014) and
        m-bootloader 2.4-395e6cc. Before you install a package, read
        "On a real FM-1"
        in the README: how to install a package, which FM-1 units it is for, and what to do when an install
        goes wrong. Keep M-VAVE's FM-1.fwsc on your computer.

      
On the FM-1, a program must keep to more rules than in this page:

      
    
        
  • C only, no C++.
    • 
        
  • float only. A double stops the build: write 0.5f,
          sinf, powf.
    • 
        
  • No malloc and no printf. The float maths and the string
          functions are there.
    • 
        
  • 464 KB of memory for the program and the platform together.
    • 
        
  • audio() is an interrupt. Do not draw in it, and draw only what changed.
    • 
      

      
The full list is in
        firmware/README.md.
        The LOG panel tells when a program does not fit the FM-1.


      
How it works

      
    
        
  1. The simulator compiler is wasm-clang by Ben Smith
          [2]:
          clang 8.0.1 and wasm-ld as WebAssembly, in a Web Worker. The page loads it from wasm-clang's demo
          site, binji.github.io/wasm-clang (about 60 MB the first time). The output is one WebAssembly module.
    2. 
        
  2. The simulator runs that module on the audio thread of the browser (an
          AudioWorklet). For each block of 256 frames it calls loop() and then
          audio(). The page shows the screen and the LEDs, and sends the keys, the encoders
          and the MIDI messages.
    3. 
        
  3. The firmware compiler is pi32v2-llvm by Julius Vitkauskas
          [5]:
          clang 23.1.5 and ld.lld for pi32v2, built from its source as WebAssembly with Emscripten
          [7]
          by FM-1 Studio, in a second Web Worker. It does the steps of fm1-base's own build, and for a
          firmware of the gallery those of the firmware's own build. For the projects that were compared,
          the package is the same bytes as the one from that build with the same compiler.
    4. 
      

      
The WebAssembly logos in the PROGRAM and FIRMWARE panels name their compiler in their hints. The
        application is one HTML file, the files of the firmware compiler, and the installer. The README
        [1]
        tells more.


      
Limits

      
    
        
  • The simulator compiler is clang 8.0.1. A program whose main loop does not return cannot run.
          COMPILE needs wasm-clang's demo site.
    • 
        
  • A project holds text files only: about 570 files and folders at most.
    • 
        
  • The LEDs are on or off: the dim levels of some firmware are not shown.
    • 
        
  • GitHub gives the list of files of a repository 60 times in an hour to one address. A firmware
          of the gallery uses one or more of these for its first load.
    • 
        
  • FIRMWARE is for fm1.h programs in C, and for the firmwares of the gallery with "yes"
          under "Real FM-1". The other firmwares of the gallery have their own builds in their repositories:
          FIRMWARE and INSTALL are off for them, and their hints tell why. INSTALL installs the program of the project only: to put the
          firmware of M-VAVE back, use a tool of M-VAVE or another installer. CS-1 0.3.4 and GR!MM 2.0.2
          know only the first flash chip of the FM-1: the page changes them when it loads them, so that they
          also take the newer chip, as AURORA does. The package of FM-106 has no Bluetooth: its Bluetooth needs closed
          libraries of JieLi. A package of an fm1.h program has no USB audio and no Bluetooth;
          USB MIDI in works.
    • 
        
  • INSTALL needs Chrome or Edge on a computer, and the page from a web server.
    •

VIBE

      

        CODE WITH AI
        a synth, a piece or a game
      

      

      
    


    

      
Vibe coding: you tell an AI what to make, the AI writes the code, and you play the
        result. You do not have to know C. The AI writes a program against fm1.h, the API of
        this page, and the FM-1 simulator runs it. PROG-1, the first card of the gallery, was vibe-coded.

      
    
        
  1. Write your idea below, or start from an example.
    2. 
        
  2. Copy the prompt, and give it to an AI chat.
    3. 
        
  3. The AI writes main.c. Copy it, and paste it on this page with Ctrl +
          V: the page compiles it and runs it in the simulator. Play it.
    4. 
        
  4. Tell the AI what to change. When a compile fails, give the AI the log.
    5. 
        
  5. SAVE the project. For a real FM-1, use FIRMWARE or INSTALL (see ABOUT).
    6. 
      


      
1. Your idea

      

        
        
        
      

      
      
Tell what it plays or does, which note keys, buttons and encoders control what, and
        what the screen shows. The prompts below take this text.


      
2. Your AI

      
An AI chat writes the program: Claude on claude.ai or in the Claude app, or another AI. You bring
        the code from the chat to this page.

      
    
        
  1. Open a new chat. Paste the prompt and send it. COPY also copies fm1.h, so that
          the AI knows the API.
    2. 
        
  2. Copy the code of the answer, and paste it on this page with Ctrl + V,
          outside the editor: the page makes a new project of it, and compiles it. A copy of the whole
          answer also works: the page takes its code. Or save the code as the file main.c,
          and drop the file on this page. SAVE your project first if you want to keep it.
    3. 
        
  3. Tell the AI what to change, and bring the new main.c to this page in the same way.
          When a compile fails, give it the log (see "Change it" below).
    4.

3. Change it

      
Give these prompts to the same AI, in the same chat.

      
The compile failed

      


FM-1 Studio gives errors for the program. Find their cause, fix it, and check the rest of main.c for the same mistake. Here is the log:

[COPY puts the text of the LOG panel here]

        
      

      
LEDs

      
The LEDs show the player which buttons to use. For a program that keeps them dark:

      


Use the LEDs to show which buttons and note keys do something. The LED of each button and control key that has a use now is on, also while nobody presses it, and the others are off. When a mode changes what the buttons do, the LEDs change with it. Show an on/off state by blinking: for example, PLAY is on while the music is stopped, and blinks with the beat while it plays. Note keys that play notes light up while their notes sound. Then tell me which LEDs are on in each mode.

        
      

      
A help page

      


Add a help page. The HOME button shows it and hides it. It tells which note keys, buttons and encoders do what. Draw the text with a small bitmap font.

        
      

      
Ready for a real FM-1

      


Check main.c for a real FM-1, and fix what breaks a rule: no double (also no constants such as 0.5 and no functions such as sin), no malloc and no printf, an audio() that is fast and does not draw, a loop() that returns soon, draws of only what changed, and small tables and buffers. Then tell me what you changed.

        
      

      
Then click FIRMWARE: it makes a package for a real FM-1, and the log tells when the program does
        not fit. Give that log to the AI with "The compile failed".


      
Good to know

      
    
        
  • Ask for one change at a time, and play the program after each change.
    • 
        
  • The page keeps nothing between visits: SAVE the project often. To continue another day, LOAD
          the zip, and give its main.c to the AI.
    • 
        
  • An AI makes mistakes. A program that works in the simulator can fail on a real FM-1. You
          install a program at your own risk: read ABOUT, and
          "On a real FM-1"
          in the README, before you use INSTALL.

INSTALL

      

        ON A REAL FM-1
        over USB, with Web MIDI
      

      

      
    


    

      
    
        
  1. READ
    2. 
        
  2. CONNECT
    3. 
        
  3. INSTALL
    4. 
      


      

        
This writes the program of this project to a real M-VAVE FM-1, in place of the
          firmware that the FM-1 has now.

        

        

        
This page was tested on one FM-1: the newer flash chip (B36014), with
          m-bootloader 2.4-395e6cc. You install at your own risk. An install that goes wrong can give an FM-1
          that does not start.

        
    
          
  • After the install, the FM-1 runs only this program, until you install another firmware.
    • 
          
  • Work with M-Flasher first.
            M-Flasher
            makes a backup of the flash of the FM-1, shows its flash chip and its boot loader, and installs
            m-bootloader:
            a boot loader with a recovery menu, and a way back to the USB download mode when a firmware does not
            start. This page was tested on an FM-1 with m-bootloader. The page cannot see the boot loader: check it
            in M-Flasher. Close M-Flasher before you click CONNECT.
    • 
          
  • Know your way back before you install: M-VAVE's own firmware, FM-1.fwsc, and a tool
            that installs it.
            "If it goes wrong"
            in the README tells what to do with an FM-1 that does not start.
    • 
          
  • The sounds and settings that the FM-1 has saved can be lost.
    • 
          
  • You need Chrome or Edge on a computer, and a USB cable that carries data.
    • 
        

        
        
        
        

      


      

        
    
          
  1. Connect the FM-1 to this computer with the USB cable, without a hub between them.
    2. 
          
  2. Switch the FM-1 on and let it start. Do not put it in an update mode.
    3. 
          
  3. Close other programs and browser tabs that use MIDI: they can keep the FM-1 busy.
    4. 
          
  4. Click CONNECT. The browser asks to let this page use MIDI devices: allow it.
    5. 
        

        
The FM-1 is not connected to the page.

            these other ports, click TRY on it:
